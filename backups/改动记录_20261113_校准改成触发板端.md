# 改动记录 2026-11-13 · 「校准」改为触发板端二次校准 + 修掉 config.js 旧基准

## 用户反馈
> 查一下 app 为什么点击校准没反应。显示双目基准已保存啥意思

## 现象
遥控器上（双目帧）点「校准」：无 loading、无按钮变化、板子无动作，只有画布底部一行小字变成
`双目基准已就地保存 (x,y) px —— 本地生效，未通知板端`。

## 根因（两条）
1. `gimbal_compare.html` 的 `calibrate()` 里，双目帧分支写完本地基准就 `return`：
   ```js
   if(frameSrc==='stereo'){ ...localStorage.setItem('stereo_ref'...)
     hint='双目基准已就地保存 ... 未通知板端'; recompute(); return; }
   ```
   即：**双目帧永远不发 `aruco/stop {"cmd":"calibrate"}`**，板端不知道点过校准。
   当初加这句的理由是“板端 calibrate 会动平台，危险”，与现场期望不一致。
2. `app/src/main/assets/config.js` 仍是旧基准 `stereoRefX 784.4 / stereoRefY 559.1 / stereoScale 0.830`，
   而 `applyConfig()` 会用它覆盖代码里的 `ST_REF_X/Y=786.0/560.0`、`ST_SCALE=0.8328`
   （`if(CFG.stereoRefX!=null)ST_REF_X=CFG.stereoRefX;`）。
   → **2026-11-10 那次“零位基准统一”在运行期被 config.js 架空了**，App 实际一直用 784.4/559.1/0.830。
   另外 `localStorage['stereo_ref']` 里如果残留旧值（以前点过校准），还会再覆盖一次。

## 改动（用户 2026-11-13 决定：跟吊舱帧一致，发板端、不写本地参考点；门槛统一 3 孔）

### 配置改动 `app/src/main/assets/config.js`
- `stereoRefX: 784.4 → 786.0`
- `stereoRefY: 559.1 → 560.0`
- `stereoScale: 0.830 → 0.8328`
- 注释补：以 零位_20261106_1203 八帧对角线交点均值 `(786.04,560.04)` 为准；旧值是 manifest 四点算术均值（差 1.1px），已作废。

### 代码改动 `app/src/main/assets/gimbal_compare.html`
1. `calibrate()` 重写：
   - 删掉双目分支的 `return` 与 `localStorage` 写基准；双目帧与吊舱帧**都**发 `aruco/stop {"cmd":"calibrate"}`，
     然后 `updateCalibButton(1)` + `lockUIFor(60000)`（收到 `aruco/calibrate/status` 或 60s 超时解锁）。
   - 门槛 `inlierIdx.length < 4` → `< 3`（与 `recompute` 一致，3 点取对角线中点）；人工补标回传也放开到 3。
   - 未配置 `calibCmd` 时显式提示，不再静默 return。
   - 提示文案：`已触发板端二次校准（双目/吊舱帧）—— 板端用深度相机自己的值；App 参考点未改，仍为零位 (786.0,560.0) px`
2. `applyConfig()`：不再读 `localStorage['stereo_ref']` 覆盖零位常量，并主动 `removeItem('stereo_ref')` 清残留。
   （吊舱 `gimbal_ref` 保留，吊舱 mm 已经是 `POD_MM=false`。）
3. 设置页「双目参考点」状态由「（默认）」改「（零位）」。

## 影响
- 现在点「校准」= 板端二次校准（平台会动），App 参考点恒定 `(786.0,560.0)/0.8328`，与 `hole_hybrid.cc` 同值。
