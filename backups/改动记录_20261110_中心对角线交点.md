## 2. 为什么改

板端自校准用「四孔矩形两条对角线交点」定中心（`hole_hybrid.cc:372-384`，透视正确）；
App 原用「4 点算术均值」(`robustCentroid`)。两者在有透视/倾斜时不是同一个点，
导致 App 的 dx/dy 与板端校准的 dx/dy 出现非固定偏差（与该帧姿态相关，无法用常数校掉）。

## 3. 具体改动

新增 `diagCenter(pts)`，`robustCentroid` 内部把两处均值换成它：

```js
/* 四孔中心 = 两条对角线交点（与板端 hole_hybrid.cc:372-384 同一算法，透视正确） */
function diagCenter(pts){
  if(!pts || pts.length<4) return null;
  const a=pts.slice().sort((p,q)=>p.y-q.y);
  const p0=a[0],p1=a[1],p2=a[2],p3=a[3];
  const TL=p0.x<p1.x?p0:p1, TR=p0.x<p1.x?p1:p0;      // 上两点定左上/右上
  const BL=p2.x<p3.x?p2:p3, BR=p2.x<p3.x?p3:p2;      // 下两点定左下/右下
  const d=(BR.x-TL.x)*(BL.y-TR.y)-(BR.y-TL.y)*(BL.x-TR.x);
  if(Math.abs(d)<1e-6) return {x:(TL.x+TR.x+BL.x+BR.x)/4,y:(TL.y+TR.y+BL.y+BR.y)/4}; // 平行退化→均值
  const num=(TR.x-TL.x)*(BL.y-TR.y)-(TR.y-TL.y)*(BL.x-TR.x);
  const k=num/d;
  return {x:TL.x+k*(BR.x-TL.x), y:TL.y+k*(BR.y-TL.y)};
}
```

- `n===4`：直接 `diagCenter(pts)`；
- `n>4`（含误点）：仍先用 `parallelogramResidual` 选最平行子集，再对选中 4 点取交点；
- 退化（两对角线平行，`|d|<1e-6`）与板端一样退化为四点均值，不会除零。

## 4. 方向核对（要求：与板端算法一致）

两边公式**同构**，都是「参考点 − 目标像素」：

| | 板端校准 | App |
|---|---|---|
| 公式 | `dx=(787−cen.x)·Z/fx`、`dy=(535−cen.y)·Z/fy` | `dx=(RX−cx)·SC`、`dy=(RY−cy)·SC` |
| dx 轴 | 横向（`cen.x`） | 横向（`cx`） |
| dy 轴 | 纵向（`cen.y`） | 纵向（`cy`） |
| 正方向 | 目标在参考点**左上** | 目标在参考点**左上** |

四象限数值核对（板：Z=900.7、fx=1081.76 → 0.833；App 双目：784.4/559.1、0.830）：

| 目标位置 | 板 dx | 板 dy | App dx | App dy | 同号 |
|---|---|---|---|---|---|
| 左上 | +130.7 | +95.8 | +128.2 | +115.5 | ✓ ✓ |
| 右上 | −127.4 | +95.8 | −129.1 | +115.5 | ✓ ✓ |
| 左下 | +130.7 | −104.1 | +128.2 | −83.7 | ✓ ✓ |
| 右下 | −127.4 | −104.1 | −129.1 | −83.7 | ✓ ✓ |
| 零位(787,535) | 0.0 | 0.0 | −2.2 | **+20.0** | ✓ **✗** |

结论：**符号约定一致，方向本来就是同一套**；唯一"看起来不一致"的是零位近旁的 dy ——
因为 App 双目参考点 y=559.1 而板端是 535（差 24px≈20mm），近零时会把 dy 顶成正。
这是参考点常量问题（见第 6 节第 2 条），不是符号问题。

## 5. 验证方法与结果
