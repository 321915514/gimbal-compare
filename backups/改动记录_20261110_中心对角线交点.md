## 2. 为什么改

板端自校准用「四孔矩形两条对角线交点」定中心（`hole_hybrid.cc:372-384`），App 原用 4 点算术均值。
透视/倾斜时两者不是同一个点，使 App 的 dx/dy 与板端校准 dx/dy 出现随姿态变化的偏差，无法用常数校掉。

## 3. 具体改动（不分形状，统一一套）

```js
/* 四孔中心 = 两条对角线交点（与板端 hole_hybrid.cc:372-384 同一算法）
   不分形状，统一：按 y 升序取上两点(左/右)、下两点(左/右)，交点 = TL-BR × TR-BL */
function diagCenter(pts){
  const a=pts.slice().sort((p,q)=>p.y-q.y);
  const p0=a[0],p1=a[1],p2=a[2],p3=a[3];
  const TL=p0.x<p1.x?p0:p1, TR=p0.x<p1.x?p1:p0;
  const BL=p2.x<p3.x?p2:p3, BR=p2.x<p3.x?p3:p2;
  const d=(BR.x-TL.x)*(BL.y-TR.y)-(BR.y-TL.y)*(BL.x-TR.x);
  const k=((TR.x-TL.x)*(BL.y-TR.y)-(TR.y-TL.y)*(BL.x-TR.x))/d;
  return {x:TL.x+k*(BR.x-TL.x), y:TL.y+k*(BR.y-TL.y)};   // 四点共线时 d=0 → NaN
}
```

- 只有一条路径：**一律取对角线交点**，不做矩形/梯形/菱形分类，不做退化形状替换（共线时 d=0 得 NaN）；
- `n===4` 直接取交点；`n>4`（有误点）仍先用原有的 `parallelogramResidual` 选最平行 4 点子集，再取交点；
- 调用方用 `Number.isFinite(c.x)` 判定：NaN 时返回 null，界面按原来的"无效"分支显示 `—`，不会把 NaN 发布到 MQTT。

## 4. 方向核对（要求：与板端算法一致）

两边公式同构，都是「参考点 − 目标像素」：

| | 板端校准 | App |
|---|---|---|
| 公式 | `dx=(787−cen.x)·Z/fx`、`dy=(535−cen.y)·Z/fy` | `dx=(RX−cx)·SC`、`dy=(RY−cy)·SC` |
| dx 轴 / dy 轴 | 横向（cen.x）/ 纵向（cen.y） | 横向（cx）/ 纵向（cy） |
| 正方向 | 目标在参考点**左上** | 目标在参考点**左上** |

四象限数值核对（板：Z=900.7、fx=1081.76 → 0.833；App 双目：784.4/559.1、0.830）：

| 右上 | −127.4 | +95.8 | −129.1 | +115.5 | ✓ ✓ |
